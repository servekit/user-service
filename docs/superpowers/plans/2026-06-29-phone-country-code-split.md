# Phone Country Code Split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the single `User.Phone` field into `PhoneCountryCode` + `Phone`, and break apart the 5 opaque `target` strings on verification/login RPCs into explicit `email` / `phone_country_code` / `phone` fields.

**Architecture:** Bottom-up migration — utility package first, then DB Model + DAL, then identity provider, then proto breaking change with simultaneous service-layer adaptation. WeChat Mini Program already returns `PurePhoneNumber` + `CountryCode`, so it slots in cleanly. `go-common/captcha` treats `target` as opaque Redis key, so we normalize to a canonical key (`<cc>|<phone>`) before calling captcha. `message-service` is **not affected** — its `SendSMSRequest.to` accepts opaque strings and parses country code internally via `nyaruka/phonenumbers`.

**Tech Stack:** Go 1.26, GORM + gorm gen, buf + protoc-gen-go, go-common (captcha, xerr), PostgreSQL, miniredis + testcontainers for tests.

**Conventions locked in:**
- Country code stored as pure digits: `"86"` (no `+` prefix).
- Phone stored as pure national number: `"13800138000"`.
- Captcha key for phone channels: `"<country_code>|<phone>"` (e.g. `"86|13800138000"`).
- Captcha key for email channels: the email string itself (unchanged).
- Import alias: `phoneutil` for `"user-service/internal/utils/phone"` — the bare `phone` name collides with field/parameter names.
- Phone identity `ProviderUID` stored as `"<country_code>|<phone>"` to match the captcha key format.

```go
// internal/utils/phone/phone.go
// Package phone normalizes and validates phone numbers and country codes
// for storage and captcha key generation.
package phone

import (
	"fmt"
	"strings"
	"unicode"
)

// NormalizeCountryCode strips optional prefixes (+, 00) and whitespace,
// returning pure digits. Returns "" for empty input.
func NormalizeCountryCode(cc string) string {
	var b strings.Builder
	for _, r := range cc {
		if unicode.IsDigit(r) {
			b.WriteRune(r)
		}
	}
	return b.String()
}

// NormalizePhone strips country-code prefix and formatting characters,
// returning pure national-number digits. Returns "" for empty input.
//
// Best-effort: if the input starts with a country code (after a +),
// the leading digits are stripped. For ambiguous cases the caller
// should pass already-separated country code + national number.
func NormalizePhone(p string) string {
	s := strings.TrimSpace(p)
	s = strings.TrimPrefix(s, "+")

	var digits []rune
	for _, r := range s {
		if unicode.IsDigit(r) {
			digits = append(digits, r)
		}
	}

	// Heuristic: if digits start with "86" and total length > 11,
	// strip the "86" prefix (China-specific shortcut for our current scope).
	if len(digits) > 11 && string(digits[:2]) == "86" {
		digits = digits[2:]
	}
	return string(digits)
}

// CaptchaKey returns the canonical key used for captcha Generate/Verify.
// For phone channels: "<country_code>|<phone>".
// For email channels (country code empty): the email string itself.
func CaptchaKey(countryCode, target string) string {
	if countryCode == "" {
		return target
	}
	return fmt.Sprintf("%s|%s", countryCode, target)
}

// Validate returns an error if country code or phone is malformed.
// Empty values are rejected.
func Validate(countryCode, phone string) error {
	cc := NormalizeCountryCode(countryCode)
	if cc == "" {
		return fmt.Errorf("phone: country code is empty")
	}
	p := NormalizePhone(phone)
	if p == "" {
		return fmt.Errorf("phone: phone number is empty")
	}
	return nil
}
```

## Risk Register

1. **Field number collisions in proto.** Each `target` → 3-field rewrite uses new field numbers. Verify each number is free in its containing message before regenerating. Risk: silent wire-compat bugs. Mitigation: Step 7a explicitly tells you to verify each number.

2. **`autoRegister` signature change cascade.** Task 7 Step 10 notes that `autoRegister` may take `target string` and may need its signature changed. Check the call site and propagate. Risk: missed call site = compile error (caught at Step 18).

3. **`User.Phone` filter on `ListUsers` semantics.** Old behavior: any phone substring match? Verify by reading `dal/user.go:286-290` — current is exact match. New behavior requires both `PhoneCountryCode` and `Phone` to filter. Risk: admin UI may break if it sends only one. Mitigation: Step 3 of Task 3 makes the filter require both fields (empty = no filter, single = no filter).

4. **Phone identity `ProviderUID` format change.** Old: phone string. New: `"<cc>|<phone>"`. If any code queries phone identities by raw phone string, it will break. Search: `grep -rn "IDENTITY_PROVIDER_PHONE" --include="*.go"` and audit each call site. Mitigation: Task 6 Step 2 + Task 7 Step 9 cover the two known sites (social.go and auth.go Register/autoRegister).

5. **Testcontainers slowness.** DAL tests use real Postgres. If Task 8 Step 1-2 is slow, run with `-short` flag or selectively. Risk: CI timeout.
